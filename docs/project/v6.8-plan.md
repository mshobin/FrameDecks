# FRAMEDECKS 6.8 — window redesign and Meeting Leader mode

The plan and the implementation record for 6.8: frameless windows with one shared ribbon, a see-through
Teleprompter overlay for Zoom, Teams and Meet, minimize to tray, a tray menu, and a system-wide Spotlight.

**Who this is for:** the maintainer and contributors.

---

## 1. Architecture audit

The request was written for Electron. FRAMEDECKS is not Electron, and 6.8 keeps it that way:

| Electron idea | FRAMEDECKS 6.8 equivalent |
| --- | --- |
| `BrowserWindow({frame: false})` | pywebview window + `desktop_win.Chrome` (Win32 `WM_NCCALCSIZE`): the title bar is removed, the sizing frame stays |
| `-webkit-app-region: drag` | `data-win-drag` on the ribbon + `POST api/app/win {op: "drag"}` → `WM_SYSCOMMAND SC_DRAGMOVE` (Windows runs the move, so Snap works) |
| `win.minimize() / maximize() / close()` | `window-chrome.js` → `api/app/win` → pywebview `minimize()`, `maximize()`, `restore()`, the app's close question |
| `transparent: true` + `setOpacity` | `desktop_win.glass` (DWM per-pixel alpha, Acrylic / blur) or `desktop_win.fade` (layered window) |
| `setAlwaysOnTop(true)` | pywebview `window.on_top` |
| `setContentProtection(true)` | `desktop_win.hide_from_capture` (`SetWindowDisplayAffinity WDA_EXCLUDEFROMCAPTURE`) |
| `Tray` | pystray (already used since 4.x) |
| `globalShortcut.register` | `desktop_win.Hotkeys` (`RegisterHotKey` on its own message-loop thread) |

Why not switch to Electron: it would add about 150 MB to the installer and 100+ MB of RAM per window on the 8 GB PCs
churches use, and replace a working Python camera engine. Everything requested is reachable with Win32 calls from
Python (ctypes), with no new package.

### What pywebview 6.2 does and does not do on Windows

- `frameless=True` removes the title bar **and** the sizing border: no resizing from the edges, no Snap, and a
  maximized window covers the taskbar. So the main windows keep their frame and `Chrome` removes only the caption.
- `transparent=True` only makes the WebView2 background transparent; the window behind it stays opaque. Real
  see-through needs the window to have per-pixel alpha: `DwmEnableBlurBehindWindow` with an empty region (the
  technique Tauri uses), plus the Windows 11 system backdrop (Acrylic) or the Windows 10 accent blur for frost.
- `on_top` works and can change at run time.
- Hidden + transparent windows are shown by pywebview on their first navigation, so Spotlight is an opaque frameless
  window (rounded by DWM on Windows 11) that is created hidden at start-up and only shown and hidden afterwards.

### Duplicated window controls

A search of `app/` for minimize / maximize / close implementations found none: every window used the Windows title
bar, and the Presentation window has no controls on purpose (it is shared in Zoom). 6.8 adds exactly one
implementation, `app/js/window-chrome.js` + `app/css/window.css`, used by every window.

## 4. Window management

- **Ribbon.** `Chrome(hwnd)` subclasses the window procedure. On `WM_NCCALCSIZE` it lets Windows compute the frame,
  then puts the top of the client area back where the window starts, so the caption disappears and the sizing borders
  (invisible on Windows 10 / 11) stay. Maximized windows overhang the screen by the frame thickness, so the top then
  keeps `SM_CYFRAME + SM_CXPADDEDBORDER`. Result: edge resizing, Snap, Aero Shake, the maximize animation, the shadow
  and Alt+Space all keep working.
- **Dragging.** The page sends `drag` once the mouse has moved 4 px with the button down (so a click and a double-click
  stay clicks). Python releases the capture and posts `SC_DRAGMOVE`; Windows runs the move loop.
- **Buttons.** Minimize (follows Settings: ask / tray / taskbar), Maximize ↔ Restore (icon follows the window state),
  Close (the main window asks "keep running in the background or quit", as before; other windows close).
- **Fallback.** Settings → General → Window and tray → *Modern window* off brings back the Windows title bar (restart).
  If Windows refuses the subclass, the title bar simply stays.

## 5. Teleprompter overlay (Meeting Leader mode)

- **Reading area.** `.tp-text` is `min(95 %, 30 × font size)` wide: 93–95 % of the window at meeting sizes, narrower only
  for small text on a very wide screen. Padding is `clamp(8px, 1.2vw, 24px)`; line height 1.55; default 44 px.
- **Floating toolbar** (`toolbar: 'float'`): Play/Pause, speed, A− / A+, line spacing, contrast, mirror, top, edit, then
  the overlay's own transparency menu, frost, stay on top and Exit. It shows on mouse movement, touch, wheel or keys and
  fades after 2.8 s (never while hovered or focused). With it hidden the pointer hides too. The ribbon (drag area and
  window buttons) fades with it. Measured: 626 × 40 px, 3.6 % of the default 1100 × 640 overlay (about 4 % with the
  two desktop-only buttons), 1.2 % of a 1920 × 1080 overlay, and nothing while hidden.
- **Transparency modes.** `body[data-mode]` sets the page's background alpha: Solid 1 · Presenter .8 · Meeting .6 ·
  Conference .35 · Ghost .14, and the halo around the letters grows as the background thins (contrast that adjusts by
  itself). Frost (`desktop_win.glass(frost=True)`) adds Acrylic on Windows 11 22H2+, blur on Windows 10.
- **Compatibility fade.** If see-through text cannot work, the window fades as a whole (`desktop_win.fade`, layered
  window alpha per mode). This is automatic while *Light on graphics card* is on: WebView2 needs GPU compositing for
  per-pixel transparency.
- **Always on top.** `overlayOnTop` (default on) is applied at creation and by the 📌 button / P key, and remembered.
- **Never shared.** `hide_from_capture` keeps the overlay (and the Teleprompter window and Spotlight) out of screen
  sharing and recordings on Windows 10 2004+.

## 6. Tray and minimize

Tray: **Open App** (default, a click opens it), **Teleprompter** (overlay on/off), **Search** (Spotlight), **Settings**,
**More ▸** (Look, Frame, Stop screen share, Hide all overlays, Presentation window, Phone remote), **Exit**. Hidden to
the tray, the window leaves the taskbar; the server, camera, overlays, phone remote and global shortcut keep running.

The minimize button asks *Hide application to system tray?* with **Hide To Tray**, **Stay In Taskbar** and *Remember my
choice*; the choice is stored in `minimizeTo` and can be changed in Settings.

## 7. Spotlight (global shortcut)

- `Hotkeys` registers the shortcut on its own thread (`RegisterHotKey`, `MOD_NOREPEAT`). Default **Alt+Space** (as in
  PowerToys Run); if another program holds it, **Ctrl+Alt+Space** is used and Settings says so. Choices: Alt+Space,
  Ctrl+Space, Ctrl+Alt+Space, Ctrl+Shift+Space, Win+Shift+K, Off.
- The Spotlight window is created hidden at start-up; the shortcut centres it on the monitor under the mouse, shows it
  on top and focuses the search box (the input arrives within one frame). Esc, choosing something, or clicking away
  hides it.
- The list comes from the main window (`KCPalette.exportIndex()` via `evaluate_js`), cached in the shared browser
  storage so the window opens with results immediately. Choosing runs `KCPalette.runKey(key)` in the main window;
  commands marked background-safe (Go Live, Next / Previous Frame, Hide all, Blackout, Freeze, Teleprompter window,
  Teleprompter overlay) leave the main window in the tray, everything else brings it forward.
- Empty search shows Recent, Frequently used and Suggested.

## 8. Visual design

Fluent caption buttons (40 × 30, icon only, Close red on hover), the existing Mica-like chrome background, rounded
corners only on floating surfaces (toolbar, Spotlight, dialogs), soft shadows, `backdrop-filter` blur on the floating
toolbar. Motion: 120–250 ms opacity / transform only (GPU-composited), all of it off with *reduce animations*.

## 9. Performance

- No new package, no new background polling. Spotlight is one hidden window; the overlay exists only while open; the
  toolbar timer runs only on input.
- The window-procedure subclass runs a few Python instructions per window message to the frame (not to the page).
- The overlay's per-pixel transparency uses the graphics card; with *Light on graphics card* on, the overlay uses
  the layered fade instead, so the setting keeps meaning what it says.

## 10. Migration

- Settings files from 6.7 load unchanged; new settings take their defaults. Nothing in the meeting data changes.
- First start of 6.8: the ribbon replaces the title bar (turn *Modern window* off to go back). Minimize asks once.
- Alt+Space opens Spotlight. People who use Alt+Space for the window menu can pick another shortcut or Off.

## 11. Testing and known risks

Tested here (Chromium, mocked desktop API): ribbon buttons and order, drag threshold and double-click, the minimize
question and remembered choice, Settings card, overlay modes / keys / pin / exit / mirror / auto-hide / reading width,
Teleprompter window layout, Spotlight search, run, Esc and groups, palette export and run. Unit tests cover shortcut
parsing and settings validation. CI runs both on Windows.

**Needs a real Windows desktop (cannot run in CI):** the window-procedure subclass, see-through glass and frost, the
layered fade, capture exclusion, the global shortcut and Spotlight focus. Each falls back to the previous behaviour if
Windows refuses it, and *Modern window* / *Compatibility transparency* switch the two riskiest parts off.
